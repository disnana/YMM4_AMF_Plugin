# MFとAMFの画質・速度を比較する

目標は「MFと同等以上の見た目を維持し、書き出しを速くする」ことです。現時点で達成済みではありません。第一弾の[待機最適化](output-wait-optimization.md)は圧縮設定を変えず、完成フレームの回収遅れを減らします。MF互換の画質プリセットではありません。

比較対象について現在聞いているのは「MFの品質固定100」で、他の設定は不明です。MFの100とAMFの「高品質」やQPに直接の対応関係は設定していません。既存の「自動 (YouTube 推奨)」もMF品質100を再現するものではありません。

## 揃えるもの

1. 同じYMM4・GPU・ドライバー、同じプロジェクト・範囲・解像度・fpsを使用します。出力設定画面全体を保存します。
2. MFは品質固定100を基準にします。コーデック、ハードウェア利用の設定、実ファイルも記録してください。AMFは同じコーデックを選び、画質・ビットレートは明示します。「同じビットレート」だけでは同等画質の証明にはなりません。
3. AMFでは待機最適化だけをOFF/ONで変えます。GPU直渡しやプール枚数も比較する場合は、別の比較として1項目ずつ変えます。
4. 別アプリなどのGPU負荷を揃え、ウォームアップ後にMF→AMF、AMF→MFの順番を交互にして各3〜5回書き出します。速度測定ではデバッグログ・プロファイリングはOFFにします。
5. 完了時間、映像品質、ファイルサイズ、音声同期、メモリ増加、終了・取消時の安定性を別々に記録します。速度だけや容量だけで合否を決めません。

高品質化のためにAMFのビットレートを増やす実験は可能ですが、その場合は容量増も結果に含めます。「同画質で速い」と「同画質・同容量で速い」は別の条件です。待機最適化自体はビットレートを増減しません。

## 共通の基準映像に対するPSNR / SSIM

```powershell
./scripts/Compare-ExportQuality.ps1 `
    -Reference 'D:/bench/rendered-lossless.mp4' `
    -MfOutput 'D:/bench/mf-quality100.mp4' `
    -AmfOutput 'D:/bench/amf-wait-on.mp4'
```

`Reference`には両エンコーダーに渡したものと同じ、圧縮前の合成済みフレームを可逆保存した動画を指定します。例えば正しい色形式・メタデータで保存したlossless H.264やFFV1です。素材を配置・加工したプロジェクトなら、素材動画そのものは基準になりません。

**MFの出力を基準に指定したり、MF出力を後から可逆形式に変換して基準を作ったりしないでください。** それでは「MF出力との近さ」しか測れず、元映像への忠実度は比較できません。基準映像を用意できない間はMF同等画質の数値判定は保留し、ON/OFFの同一性と目視確認を先に行います。

対象はSDR BT.709・limited range・8bit YUV420（`yuv420p`）です。全ファイルで同一解像度・fps・デコードフレーム数・CFR時刻列を検証します。時刻は先頭からの相対位置で照合し、コンテナの丸めに2msの許容を設けています。条件が合わない場合や色メタデータが不明な場合は停止します。勝手なリサイズ・色変換・フレーム補間・末尾フレームの繰り返しは行いません。

可逆マスターをこの形式へ変換する必要がある場合は、色空間・range・クロマ変換を別途明示し、両者に共通の基準として扱ってください。RGB/HDR/10bitや異なる色変換自体の評価は、このツールの範囲外です。テストを通すためだけに未知の映像へBT.709タグを付けるのは不適切です。

結果は毎回別の`artifacts/runs/export-quality-.../`へ保存します。入力動画の変更・外部送信は行いません。

- `summary.json`: 入力のSHA-256・サイズ・形式、各出力のPSNR、SSIM平均・最小・p05・p50、MFとの比較指標。
- `mf.psnr.log` / `amf.psnr.log` / `mf.ssim.log` / `amf.ssim.log`: 全フレームの数値。平均が良くても一部フレームに劣化がないか調べます。
- `*.probe.json` / `*.ffmpeg.log` / `ffmpeg-version.txt`: フレーム時刻・解析ログ・ツール版。ローカルパスを含むので公開前に確認します。

PSNRはフレームごとのdBを平均せず、FFmpegが平均MSEから算出する集約値を使います。無限大はJSON文字列`"inf"`で記録します。SSIMのp05は低品質側5%点、p50は中央値（nearest-rank）です。[FFmpeg公式のPSNR](https://ffmpeg.org/ffmpeg-filters.html#psnr)・[SSIM](https://ffmpeg.org/ffmpeg-filters.html#ssim)仕様に基づきます。

比較指標がすべて良くても、自動で「MF以上の見た目」とは判定しません。SSIM/PSNRは圧縮ノイズ・細かい文字・髪・輪郭・フェード・動きの主観的な見え方を完全には表しません。時間軸や枚数が同じでも同一内容だとは証明できないため、冒頭・中盤・末尾のフレーム対応も確認してください。音声や聴感上の同期は別検証です。

解析にかかった時間はエンコーダーの速度ではありません。反復書き出し時間と合わせて判断します。

## テスト

```powershell
./tests/Test-ExportQuality.ps1              # CPUのみ、ffmpeg不要
./tests/Test-ExportQuality.ps1 -Integration # ffmpeg/ffprobeが必要
```

形式不一致・VFR・フレーム欠落・集計方法を検証します。統合テストの可逆/非可逆サンプルはCPUで生成した比較ツール用のfixtureで、MF対AMFの実性能結果ではありません。既存CIのUnit実行にCPU側の契約テストを含めています。実GPUの品質・性能・安定性はローカルで別に検証します。
