# YMM4 Radeon (AMF) v0.2.2

Disnana Project / 開発: [tp-li-dev](https://github.com/tp-li-dev)

MP4に記録する音声トラックの長さ情報を修正しました。旧版では、音声データが動画の最後まで残っていても、再生・変換するアプリによって後半の音声が短く扱われる可能性があります。通常設定・実験設定に共通するMP4出力処理の修正です。

48 kHz音声では、4分の音声が一部の長さ情報では2分08秒相当になっていました。v0.2.2では、その情報を正しい時間単位で記録します。音声の圧縮方式・音量、映像の画質・ビットレート、推奨設定は変更していません。

今回の報告ではWindows上で正常に音声を再生でき、FFmpegでも最後まで復号できました。音声データ自体は残っていたため、従来の再生確認・音声長検査ではヘッダーの不整合を見つけられず、発見が遅れる要因になりました。今回、データの長さとヘッダーの長さを照合する検査を追加しています。

## 確認した範囲

- 報告された約5分28秒のMP4で、AAC音声は最後まで復号できる一方、音声トラックのヘッダーが約2分55秒相当になっていることを確認しました。
- 32 / 44.1 / 48 kHz音声と4分の動画を使った回帰検査を追加しました。既存の全デコード・音声長検査に、MP4ヘッダーの時間単位の検査も追加しています。
- 修正ビルドでH.264 / HEVCの出力と、4分のHEVC非同期出力を検査しました。全フレームの復号・順序、色メタデータ、音声の長さ、MP4ヘッダーの整合を確認しています。
- LINE経由でiPhoneへ送った出力に音声欠落の報告があります。長さ情報の誤りは確認済みですが、修正版を同じ送信・再生手順で確認する端末試験は未完了です。

## 更新方法

プロジェクトを保存してYMM4を終了し、Assetsの`YMM4-Radeon-AMF-v0.2.2.ymme`を開いて更新してください。手動更新では`AMFPlugin.dll`と`AmfNative.dll`を同じパッケージからセットで更新します。

修正はこれから書き出すMP4へ適用されます。旧版で書き出した動画は、v0.2.2で再出力してください。
