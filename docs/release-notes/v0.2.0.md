# YMM4 Radeon (AMF) v0.2.0

Disnana Project / 開発: [tp-li-dev](https://github.com/tp-li-dev)

動画出力の診断機能と、実験的なGPU入力経路の切り替えを追加しました。いずれも既定OFFです。エンコード方式・品質・所有テクスチャプールの既定動作は維持しています。速度向上を保証するリリースではありません。

## 追加した機能

- **GPU直渡し（実験・IVideoFileWriter3）**：AMFの出力設定からON/OFFできます。YMM4側のCpuReadビットマップへの中間コピーを省く経路です。AMFの所有テクスチャへのGPUコピーは残るため、完全Zero Copyではありません。Harmonyや別ツールは不要です。
- **プロファイリング結果を書き出す（集計JSON）**：映像・音声の受け取り、ロック、pool待ち、SubmitInput、QueryOutput、Mux、終了処理の回数・合計・平均・最大時間を`出力名.amf_profile.json`へ保存します。デバッグログとは独立しています。
- **計測専用：映像・音声を破棄**：受け取った映像・音声をプラグインで処理せず返し、MP4を生成しません。プロファイリングと組み合わせ、出力側と上流側を切り分けるための診断モードです。GPU直渡しOFFでは、YMM4側の入力前コピーは残ります。
- 設定は出力開始時に固定されます。実行中にチェックを変えても進行中の出力は切り替わりません。

## 動作条件・更新手順

`IVideoFileWriter3`を持つ.NET 10対応YMM4が必要です。API・ローカルテストと実プロジェクトログはYMM4 v4.56.1.1で確認しています。古いAPIのYMM4では、GPU直渡しをOFFにしてもプラグインを読み込めません。

1. 制作プロジェクトを保存してYMM4を終了します。
2. Assetsの`YMM4-Radeon-AMF-v0.2.0.ymme`を開いてインストールします。
3. YMM4を再起動し、まず追加チェックをすべてOFFにして短い区間を別名で出力・再生確認します。

手動更新では`AMFPlugin.dll`と`AmfNative.dll`を必ずセットで更新してください。YMM4本体のDLLは配布物に含めません。SHA-256ファイルを添付します。

## 確認した範囲

- ローカルCPU側の43チェック：ABI、集計、破棄時native呼び出し禁止、UI、入力経路、設定スナップショットなど。
- RX 6800 XTで、管理WriterのH.264/HEVC × GPU直渡しOFF/ON × profile OFF/ONの8ケース、既存nativeベンチ4ケース。
- 各ケース640×360・60fps・120フレーム、AAC付き。全デコード・フレーム数と順序・BT.709 limitedメタデータ・映像/音声duration差の検査を通過。
- 実プロジェクトのH.264ログで、GPU直渡しOFF/ONとも7,259フレームの投入・完了・最終化を確認。OFF約39.88秒、ON約41.30秒の各1回で、GPU直渡しによる高速化は確認できていません。設定・素材・GPUにより結果は変わります。

ローカル実GPUテスト、GitHub ActionsのCPUテスト、YMM4実プロジェクトログは別の検証です。音声はduration、色はメタデータの検査で、厳密な音ズレ・画素値・画質評価ではありません。

## 制限

- 計測はCPU側の経過時間です。GPU実行時間、フレーム別時系列、p50/p95/p99、AMF内部キュー深さ、GPU使用率、GC pauseはこの版では記録しません。
- 入れ子・並列処理の集計値は重なります。待機時間を合計して短縮余地と解釈しないでください。
- 長時間反復、キャンセル、device removal、HEVCのYMM4実プロジェクト、複数GPU/ドライバーの網羅検証は未完了です。
- 診断時は新しい出力名を使ってください。破棄モードは既存MP4を更新せず、同名profile JSONは最新結果で置き換えます。設定の永続保存はありません。
- 動画出力プラグインのみのリリースです。観測用PoC、MF解析、新しい圧縮/待機オプションは含みません。
